# 프로세스와 스레드

## 한 줄 요약

프로세스는 OS로부터 **자원을 할당받는 단위**이고, 스레드는 그 자원을 공유하면서 **CPU를 받아 실행되는 단위**예요.

## 프로세스 vs 스레드

| | 프로세스 | 스레드 |
|---|---|---|
| 정체 | 메모리에 올라간 실행 중인 프로그램 | 프로세스 안의 실행 흐름 |
| 주소 공간 | 프로세스마다 독립 | 같은 프로세스 안에서 공유 |
| 개수 | - | 프로세스당 최소 1개(메인 스레드)부터 여러 개 |
| 통신 | IPC 필요 (파이프, 소켓 등) | Heap 등 공유 메모리로 바로 |

## 메모리 구조에서 무엇을 공유하나

| 영역 | 스레드 간 |
|---|---|
| Code, Data, Heap | **공유** |
| Stack, 레지스터(PC 포함) | **스레드마다 따로** |

- 스레드끼리는 Heap의 객체를 바로 주고받을 수 있어요. 대신 같은 데이터를 동시에 건드리면 동기화 문제가 생겨요.
- CPU 스케줄링은 **스레드 단위**로 일어나요. 멀티코어면 한 프로세스의 스레드들이 여러 코어에서 동시에 돌 수 있어요.

## 컨텍스트 스위칭

CPU가 실행 대상을 바꿀 때 현재 상태(레지스터 등)를 저장하고 다음 대상의 상태를 복원하는 작업이에요.

- **스레드 간 전환**: 주소 공간이 같아서 레지스터와 스택 포인터만 바꾸면 돼요.
- **프로세스 간 전환**: 주소 공간이 바뀌어서 페이지 테이블을 교체해요. 그러면 **TLB가 무효화**되고 CPU 캐시도 못 써서 전환 직후 캐시 미스가 많아요.
- 스택·레지스터 저장/복원은 둘 다 똑같아요. 차이는 **메모리 컨텍스트를 바꾸느냐**예요.

## 멀티프로세스 vs 멀티스레드

| | 장점 | 단점 |
|---|---|---|
| 멀티프로세스 | 메모리 격리(하나 죽어도 나머지 무사), 보안 샌드박스 | 메모리 많이 씀, 전환 비용 큼, IPC 필요 |
| 멀티스레드 | 생성·전환이 가볍고 데이터 공유 쉬움 | 동기화 문제(경쟁 조건, 데드락), 한 스레드 크래시가 프로세스 전체에 영향 |

- **크롬**: 탭 하나가 죽거나 악성 페이지를 열어도 다른 탭이 안전해야 해서 탭마다 프로세스를 써요.
- **톰캣**: 요청마다 프로세스를 띄우면 너무 무겁고, 빈·캐시·커넥션 풀을 요청끼리 공유해야 해서 스레드를 써요. 대신 동기화는 직접 신경 써야 해요.
