# 가상 메모리

## 한 줄 요약

프로세스마다 **자기만의 가상 주소 공간**을 주고, 필요한 부분만 물리 메모리에 올려서 한정된 메모리를 효율적으로 쓰는 기술이에요.

## 왜 필요한가

- **격리와 보호**: 가상 메모리가 없으면 물리 주소를 직접 써서, 주소만 알면 다른 프로세스나 커널 영역까지 읽고 쓸 수 있어요. 버그 하나가 시스템 전체를 죽일 수 있어요.
  - 가상 메모리가 있으면 프로세스의 페이지 테이블에 **자기 소유 페이지만** 등록돼 있어서 남의 메모리로 가는 길이 없어요. 매핑되지 않은 주소에 접근하면 MMU가 막고 OS가 프로세스를 종료시켜요 (`Segmentation fault`).
  - 프로세스 A의 `0x1000`과 B의 `0x1000`은 서로 다른 물리 메모리에 매핑돼요.
- **편리함**: 각 프로그램이 물리 메모리 배치를 신경 쓰지 않고 0번지부터 연속된 큰 공간을 쓰는 것처럼 짤 수 있어요.
- **물리 메모리보다 큰 프로그램 실행**: 아래 동작 방식 참고

## 동작 방식

1. 프로세스는 **가상 주소**로 메모리에 접근해요.
2. **MMU**가 페이지 테이블을 보고 가상 주소를 물리 주소로 바꿔요.
3. 변환 결과는 **TLB**(CPU 안의 캐시)에 담아 둬서 다음엔 빠르게 변환해요. 페이지 테이블은 메모리에 있어서 매번 찾으면 느려요.
4. 프로그램 전체가 아니라 **지금 필요한 페이지만** 물리 메모리에 올려요. (demand paging)
5. 나머지는 디스크(swap 영역)에 두고, 없는 페이지에 접근하면 **page fault**가 나요. OS가 디스크에서 불러와요.

## 스레드와의 관계

- 같은 프로세스의 스레드는 페이지 테이블을 같이 써서 Heap을 공유할 수 있어요.
- 프로세스가 바뀌면 페이지 테이블이 바뀌어서 TLB가 무효화돼요. 그래서 프로세스 컨텍스트 스위칭이 스레드보다 무거워요.
