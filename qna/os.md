### 2026-11-27 — 프로세스 vs 스레드
**Q. 프로세스와 스레드의 차이는? 메모리 관점에서 무엇을 공유하나요?**
- 프로세스는 자원을 할당받는 단위, 스레드는 그 자원을 공유하며 CPU를 받아 실행되는 단위. 프로세스는 최소 1개부터 여러 개의 스레드를 가짐
- Code, Data, Heap은 스레드 간 공유, Stack과 레지스터는 스레드마다 따로

### 2026-11-27 — 컨텍스트 스위칭
**Q. 스레드 간 컨텍스트 스위칭이 프로세스 간보다 가벼운 이유는?**
- 스택·레지스터 저장/복원은 둘 다 같음. 프로세스 전환은 주소 공간이 바뀌어 페이지 테이블 교체 → TLB 무효화 + CPU 캐시 미스 증가
- 스레드는 같은 주소 공간이라 레지스터와 스택 포인터만 바꾸면 됨

### 2026-11-27 — 멀티프로세스 vs 멀티스레드
**Q. 크롬은 탭마다 프로세스, 톰캣은 요청마다 스레드를 쓰는 이유는?**
- 멀티프로세스는 격리(하나 죽어도 나머지 무사, 보안)가 장점, 메모리·전환 비용과 IPC가 단점
- 멀티스레드는 가볍고 공유가 쉬운 대신 동기화 문제와 한 스레드 크래시 전파가 단점
- 톰캣은 빈·캐시·커넥션 풀을 공유해야 해서 스레드, 크롬은 탭 격리를 위해 프로세스

### 2026-11-27 — 경쟁 조건
**Q. 두 스레드가 공유 변수 `count++`를 1000번씩 실행하면 왜 2000이 안 나올 수 있나요? 해결은?**
- `count++`는 읽기→더하기→쓰기라 원자적이지 않아 같은 값을 읽고 각자 쓰면 lost update (경쟁 조건), 공유 자원을 건드리는 구간이 임계 영역
- 해결: 락(뮤텍스, `synchronized`), 원자 연산(`AtomicInteger`, CAS), 공유 피하기(스레드 로컬, 불변 객체)

### 2026-11-27 — 뮤텍스 vs 세마포어
**Q. 뮤텍스와 세마포어의 차이는?**
- 뮤텍스: 1개 스레드만, 소유권 있음(잡은 스레드만 해제), 상호 배제용
- 세마포어: 카운터로 N개까지, 소유권 없음(다른 스레드가 signal 가능), 동시 접근 수 제한·스레드 간 신호 전달용
- 소유권 = 동시에 몇 명이냐가 아니라 누가 락을 풀 수 있느냐

### 2026-11-27 — 데드락
**Q. 데드락이란? 발생 조건 4가지는?**
- 서로 필요한 자원을 쥔 채 기다려 영원히 멈추는 상태
- 상호 배제, 점유 대기, 비선점, 순환 대기. 네 개가 모두 충족돼야 하고 하나만 깨도 예방됨
- 실무: 락 획득 순서 고정, `tryLock(timeout)`

### 2026-11-27 — 이체 데드락
**Q. A→B, B→A 이체가 동시에 일어나 둘 다 `from` 락을 먼저 잡으면?**
- 서로 상대 락을 쥔 채 대기 → 순환 대기로 데드락
- 이체 방향과 무관하게 계좌 ID가 작은 쪽 락을 먼저 잡아 순서 통일. `tryLock(timeout)`은 보조 장치

### 2026-11-27 — 가상 메모리
**Q. 가상 메모리는 왜 필요하고, 물리 메모리보다 큰 프로그램을 어떻게 실행하나요?**
- 프로세스마다 독립된 가상 주소 공간을 주어 격리·보호(남의 메모리로 가는 매핑 자체가 없음). MMU가 페이지 테이블(+TLB)로 가상→물리 변환
- 필요한 페이지만 물리 메모리에 올리고 나머지는 디스크(swap). 없는 페이지 접근 시 page fault → OS가 로드
